# How to Interpret Hierarchical Token Pattern Visualizations

This guide explains how to read and interpret each visualization generated by the hierarchical token pattern analysis.

---

## 1. Rollout Similarity Matrix (`rollout_similarity_matrix.png`)

### What it shows
A heatmap showing how similar each rollout is to every other rollout based on their token usage patterns, with hierarchical clustering dendrograms on both axes.

### Structure
```
┌──────────┬─────────────────┐
│          │  Dendrogram     │
│  Empty   │  (top)          │
├──────────┼─────────────────┤
│ Dendro-  │                 │
│ gram     │   Heatmap       │
│ (left)   │                 │
└──────────┴─────────────────┘
```

### How to interpret

**Color Scale:**
- **Dark (low values)**: Rollouts share few tokens → Very different behaviors
- **Bright (high values)**: Rollouts share many tokens → Very similar behaviors
- **Diagonal**: Always bright (similarity = 1.0) since each rollout is identical to itself

**Dendrograms:**
- Show hierarchical clustering structure
- **Height of branches**: Represents dissimilarity between clusters
  - **Short branches**: Rollouts/clusters are very similar
  - **Tall branches**: Rollouts/clusters are quite different
- **Leaf ordering**: Rollouts are reordered to place similar ones adjacent

**Block patterns in heatmap:**
- **Clear blocks of bright colors**: Strong cluster structure exists
  - Indicates distinct behavioral "modes" or "regimes"
  - Example: 3 bright squares along diagonal = 3 main clusters
- **Uniform gradient**: Weak or no cluster structure
  - Tokens vary smoothly across rollouts without discrete groups
- **Stripe patterns**: Hierarchical sub-clustering
  - Larger clusters contain smaller sub-clusters

**Key insights:**
- **"Singleton" re-evaluation**: If you see bright off-diagonal regions, many rollouts labeled as "singletons" actually share 80%+ of their tokens
- **Cluster count**: Number of distinct bright blocks ≈ number of behavioral modes
- **Cluster size**: Size of bright blocks indicates how many rollouts belong to each mode

## 2. Token Commonality Analysis (`token_commonality_*.png`)

### What it shows
Three complementary views of how tokens are distributed across rollouts for a specific category and level.

### Panel 1: Top Tokens by Frequency (Left)
**Horizontal bar chart showing the most frequently used tokens**

**Y-axis**: Token IDs (e.g., "Token 5", "Token 12")
**X-axis**: Frequency (number of rollouts using this token)

**How to interpret:**
- **Long bars**: Common tokens used by many rollouts
- **Short bars**: Rare tokens used by few rollouts
- **Steep drop-off**: Power-law distribution (Zipfian)
  - Natural for most tokenizers
  - A few tokens dominate, many are rare
- **Flat distribution**: More uniform token usage
  - Each token is used by similar number of rollouts
  - May indicate under-utilized codebook capacity

**Key questions:**
- Is there a "winner-take-all" token? (One token >> all others)
- How many tokens are actually being used? (Count bars visible)

### Panel 2: Token Frequency Distribution (Middle)
**Histogram of token frequencies across the entire category**

**X-axis**: Frequency (how many rollouts use a token)
**Y-axis**: Count (how many tokens have this frequency)

**How to interpret:**
- **Peak at low frequencies**: Many tokens are rare (used by <10% of rollouts)
- **Peak at high frequencies**: Many tokens are common (used by >50% of rollouts)
- **Bimodal distribution**: Two peaks = two regimes
  - Example: Peak at freq=1 (singletons) + peak at freq=500 (universal)
  - Suggests some tokens are "signature" (unique to one rollout) vs "shared" (used everywhere)

**Key insights:**
- **Singleton peak**: How many tokens appear in only 1 rollout?
- **Common peak**: How many tokens are "always-on" features?
- **Distribution shape**: Power-law (long tail) vs normal vs bimodal

### Panel 3: Token Commonality Pie Chart (Right)
**Classification of tokens into usage categories**

**Common (≥50% of rollouts)**: Green
- Tokens that appear in at least half of all rollouts
- "Universal" features shared across most behaviors

**Medium**: Orange
- Tokens used by 10-50% of rollouts
- Moderately shared features

**Rare (<10% of rollouts)**: Red
- Tokens used by fewer than 10% of rollouts
- Specialized features for niche behaviors

**Singleton (1 rollout)**: Gray
- Tokens that appear in exactly one rollout
- Unique "fingerprint" features

**How to interpret:**
- **Large green slice**: High token sharing → rollouts are similar
- **Large gray slice**: Many unique tokens → rollouts are diverse
- **Balanced distribution**: Mix of shared and unique tokens
  - Healthy tokenizer with good capacity utilization

**What to look for:**
- **Ideal**: Mostly medium + some rare/common (good diversity)
- **Problem**: Mostly singleton or mostly common
  - **Mostly singleton**: Codebook not learning shared structure
  - **Mostly common**: Codebook not capturing diversity

## 3. Token Set Intersections (`token_intersections_upset.png`)

### What it shows
Which combinations of categories frequently co-occur with tokens across rollouts.

### Format: Simplified UpSet Plot
**Horizontal bar chart with special labels**

**Y-axis**: Intersection patterns (e.g., "temporal_1 ∩ temporal_11 ∩ temporal_12")
**X-axis**: Intersection size (number of rollouts with tokens in all categories)

### How to interpret

**Single-category bars** (e.g., "temporal_1"):
- Rollouts that have tokens in ONLY this category
- High value = many rollouts use only this category
- Indicates category is often used in isolation

**Multi-category bars** (e.g., "temporal_1 ∩ temporal_11"):
- Rollouts that have tokens in ALL listed categories
- High value = strong co-occurrence pattern
- Indicates these categories are frequently used together

**Pattern significance:**
- **Many large single-category bars**: Categories are independent
  - Rollouts typically activate only one category at a time
- **Many large multi-category bars**: Categories are correlated
  - Rollouts typically activate multiple categories together
- **Decreasing bar heights**: More categories = fewer rollouts
  - Natural: harder to satisfy more constraints

**Key insights:**
- **Compositional structure**: Which categories work together?
- **Category independence**: Can categories be used separately?
- **Dominant patterns**: What are the most common token combinations?

**Example interpretation:**
```
temporal_1: 500 rollouts
temporal_1 ∩ temporal_11: 450 rollouts
temporal_1 ∩ temporal_11 ∩ temporal_12: 400 rollouts
```
→ These three categories are highly correlated. If a rollout uses temporal_1, it almost always also uses temporal_11 and temporal_12.

## 4. Token Co-occurrence Network (`token_cooccurrence_network.png`)

### What it shows
A network graph where tokens are nodes and co-occurrence across rollouts defines edges.

### Visual elements

**Nodes (circles)**: Individual tokens
- **Size**: Proportional to token frequency
  - **Large nodes**: Frequently used tokens
  - **Small nodes**: Rarely used tokens
- **Color**: Category family
  - **Green**: Temporal features
  - **Red**: Spatial features
  - **Orange**: Spectral features

**Edges (lines)**: Co-occurrence relationships
- **Presence of edge**: Two tokens appear together in ≥ min_cooccurrence rollouts
- **Width**: Proportional to co-occurrence frequency
  - **Thick edges**: Tokens frequently co-occur
  - **Thin edges**: Tokens occasionally co-occur

**Labels**: Only shown for high-frequency nodes to avoid clutter

### How to interpret

**Network structure:**
- **Dense clusters**: Groups of tokens that frequently appear together
  - Indicates "token communities" or "feature bundles"
  - Example: All tokens in a cluster might represent "high-frequency oscillation" behavior
- **Isolated nodes**: Tokens that rarely co-occur with others
  - May be "signature" tokens for specific rare behaviors
- **Hub nodes**: Large nodes with many connections
  - "Universal" tokens that appear with many other tokens
  - Often represent baseline or common features

**Connectivity patterns:**
- **Fully connected cluster**: Tokens always appear together
  - Strong compositional structure
  - May indicate feature redundancy
- **Star pattern**: One hub connected to many satellites
  - Hub token is ubiquitous
  - Satellite tokens are conditionally used with hub
- **Multiple separate clusters**: Multiple independent behavioral modes
  - Each cluster represents a distinct regime

**Edge analysis:**
- **Thick edges within cluster**: Strong internal correlation
- **Thin edges between clusters**: Weak cross-cluster correlation
- **No edges between clusters**: Independent behavioral modes

**Key insights:**
- **Community detection**: How many distinct token "neighborhoods" exist?
- **Token redundancy**: Are some tokens always together? (candidates for merging)
- **Behavioral regimes**: Do clusters correspond to known physics regimes?

**Example interpretation:**
```
Cluster 1 (left): 10 green nodes densely connected
Cluster 2 (right): 8 green nodes densely connected
Few edges between clusters
```
→ Two distinct temporal behavioral modes with different token usage patterns.

## Putting It All Together: Workflow for Analysis

### Step 1: Check similarity matrix for cluster structure
- **Clear blocks?** → Proceed to identify clusters
- **No blocks?** → Tokens vary smoothly, no discrete modes

### Step 2: Examine token commonality
- **Many singletons?** → High diversity, investigate unique behaviors
- **Many common?** → Low diversity, check if codebook is underutilized
- **Balanced?** → Healthy distribution

### Step 3: Identify compositional patterns
- **Intersection plot**: Which categories co-occur?
- **Network graph**: Which tokens form communities?

### Step 4: Interpret findings
- **Strong clusters + few common tokens** → Distinct behavioral regimes
- **Weak clusters + many common tokens** → Smooth variation around baseline
- **Correlated categories** → Compositional structure (features work together)
- **Independent categories** → Modular structure (features are orthogonal)

## Common Patterns and Their Meanings

### Pattern 1: Strong Clustering
**Observations:**
- Clear bright blocks in similarity matrix
- Bimodal token frequency distribution
- Distinct clusters in co-occurrence network

**Meaning:**
- Rollouts fall into distinct behavioral categories
- VQ-VAE has learned discrete "modes" or "regimes"
- Tokenizer is effectively compressing similar behaviors

**Implications:**
- Good for downstream classification tasks
- Agent can explore different behavioral modes
- May want to analyze what each cluster represents physically

### Pattern 2: Smooth Variation
**Observations:**
- Gradient in similarity matrix (no clear blocks)
- Unimodal token frequency distribution
- Diffuse co-occurrence network

**Meaning:**
- Rollouts vary continuously rather than categorically
- No discrete behavioral modes
- Tokenizer represents smooth manifold

**Implications:**
- Good for interpolation tasks
- Agent explores continuous behavior space
- May need more tokens to capture fine-grained variation

### Pattern 3: Singleton Dominance
**Observations:**
- Large gray slice in commonality pie chart
- Many small bars in token frequency histogram
- Sparse co-occurrence network

**Meaning:**
- Each rollout uses unique token combinations
- Low token sharing across rollouts
- Codebook may not be learning shared structure

**Implications:**
- Check if dataset is too diverse
- Consider increasing training or codebook size
- May indicate under-training or overfit codebook

### Pattern 4: Common Token Saturation
**Observations:**
- Large green slice in commonality pie chart
- Few active tokens (most unused)
- Dense hub-and-spoke network

**Meaning:**
- Most rollouts use the same small set of tokens
- Codebook capacity is underutilized
- May indicate mode collapse or insufficient diversity

**Implications:**
- Generate more diverse training data
- Check if regularization is too strong
- May need to adjust commitment loss weight

## Diagnostic Questions

Use these visualizations to answer:

1. **Is my tokenizer learning meaningful structure?**
   - Check similarity matrix for clusters
   - Check commonality for balance between shared/unique

2. **Are rollouts truly diverse or just superficially different?**
   - High similarity + many singletons → diverse tokens, similar structure
   - Low similarity + few common → truly diverse behaviors

3. **Which categories are important?**
   - Intersection plot shows which categories co-occur
   - Network shows which tokens are central vs peripheral

4. **Is my codebook being fully utilized?**
   - Token frequency histogram shows utilization
   - Many unused tokens → consider smaller codebook or more diverse data

5. **What are the main behavioral modes in my dataset?**
   - Similarity matrix clusters
   - Co-occurrence network communities
   - Cross-reference with physics domain knowledge

## Next Steps After Analysis

Based on your findings:

**If you see strong clustering:**
- Label clusters with physical interpretations
- Ensure all important physics regimes are represented
- Consider using cluster labels for downstream tasks

**If you see singleton dominance:**
- Generate more training samples
- Retrain with longer training or different hyperparameters
- Check feature engineering (may need better features)

**If you see common token saturation:**
- Increase dataset diversity (wider parameter ranges)
- Reduce codebook size (fewer tokens per level)
- Adjust VQ-VAE loss weights (reduce commitment loss)

**If you see smooth variation:**
- This may be correct for your domain!
- Ensure sufficient tokens to represent manifold
- Consider dimensionality reduction on token space
